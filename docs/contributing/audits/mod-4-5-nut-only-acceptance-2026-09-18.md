# MOD-4 / MOD-5 NUT-only implementation and acceptance

Components: Modular Deployment Profiles; NUT Server / upsd.
Audience: contributors.

Date: 2026-09-18.
Owners: MOD-4, MOD-5 and the NS-11 upstream compatibility dependency.

## Implementation

The same manager binary accepts `--profile=full|nut-only`. Full remains the default. NUT-only
registers only NUTServer reconciliation and UPSDevice/NUTServer admission and requires an
explicit distribution-supplied default operand image. Disabling admission or misspelling the
profile fails startup. The renderer refuses management-cluster references before any API access.

`make build-installer-nut-only` derives the profile from canonical generated BYO-cert resources.
It keeps two CRDs, two mutating/two validating entries, manager infrastructure and a restricted
RBAC intersection. It omits agents, planner, inventory, node permissions and database resources.
The existing webhook certificate script bootstraps/rotates the serving certificate. The bundle
is covered by the existing hygiene regeneration check.

`NUTServer.spec.clientAccess` grants additional cross-namespace clients with explicit namespace
and optional pod selectors. It preserves existing same-namespace/manager access. Secrets using
ExistingSecret auth now enqueue their referencing servers on rotation, in addition to existing
TLS/device credential watches. The two-container operand and driver recovery implementation
are reused. The [installation guide](../../installation/nut-only.md) owns user-facing instructions.

## NS-11 compatibility choice

The pinned operand's `dummy-ups` has no `authconf` option. Plain repeater configuration now omits
it; both admission and renderer validation reject Default/Secret auth modes. Requested upstream
credentials or verified-TLS policy are never silently discarded. `None` supports unauthenticated
upstream reads, with no certificate verification. Downstream TLS/users are a separate boundary.
See the [pinned source](https://github.com/networkupstools/nut/blob/v2.8.5/drivers/dummy-ups.c)
and [relay contract](../design/upstream-nut-relay.md).

## Qualification boundaries

The installer is an alternative to a full installation, not an in-place migration or concurrent
second manager. Reapplication/restart tests do not establish compatibility with every historical
schema. Variable reads follow NUT semantics and need network restriction; monitor credentials
do not gate every read. External clients enforce verified TLS; upsd still accepts plaintext
protocol connections. No verified-TLS upstream relay, mutual TLS, external-CIDR routing, physical
UPS or guest power-off is claimed. Hadron/Talos work is separate and untouched.

Trivy is unavailable on this host; no scanner was installed. The existing Checkov scanner ran
offline against the generated installer: 123 checks passed, one failed, two were suppressed by
existing source annotations. The one finding, CKV_K8S_15, requests `imagePullPolicy: Always`.
It is triaged as the existing deliberate install policy: `config/manager/manager.yaml` keeps
IfNotPresent for preloaded test images, while production deployment must select immutable image
digests. Changing to Always breaks the isolated loaded-image workflow and adds no content
integrity for digest-pinned images. The profile preserves that policy and documents digest
selection; this is not a clean scanner pass or an image-vulnerability scan result.
